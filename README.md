# LinkedIn Job Parser

Django-застосунок для збору, збереження, обробки та експорту даних про вакансії з LinkedIn. Проєкт використовує PostgreSQL для зберігання інформації та Django ORM для роботи з базою даних.

## Можливості

- **Збір вакансій** — пошук і збереження вакансій за заданими параметрами.
- **Збереження даних** — зберігання вакансій і компаній у PostgreSQL.
- **Збагачення вакансій** — отримання опису, типу зайнятості та рівня посади (Seniority).
- **Збагачення компаній** — отримання опису компанії, галузі, вебсайту та кількості працівників.
- **Обробка помилок** — відстеження статусу обробки вакансій, кількості спроб і останніх помилок.
- **Django Admin** — перегляд і керування збереженими вакансіями та компаніями.
- **Експорт в Excel** — вивантаження вакансій і компаній в один `.xlsx` файл на окремі аркуші.
- **Налаштування через `.env`** — конфігурація бази даних і параметрів Django через змінні середовища.

## Технології

- **Python 3.13** — основна мова програмування.
- **Django** — вебфреймворк та ORM.
- **PostgreSQL** — основна база даних.
- **BeautifulSoup** — обробка HTML-сторінок.
- **Requests** — HTTP-запити для отримання вебсторінок.
- **OpenPyXL** — створення та форматування Excel-файлів.
- **SQLite** — може використовуватися для локальної розробки або попередньої версії бази даних, якщо це передбачено конфігурацією проєкту.

## Встановлення та запуск

### 1. Клонування репозиторію

```bash
git clone https://github.com/Inefan/linkedin-job-parser.git
cd linkedin-job-parser
```

Заміни `YOUR_USERNAME` на свій логін GitHub.

### 2. Створення віртуального середовища

Для Windows CMD:

```bash
python -m venv venv
venv\Scripts\activate
```

### 3. Встановлення залежностей

```bash
pip install -r requirements.txt
```

### 4. Налаштування змінних середовища

Створи файл `.env` у кореневій папці проєкту на основі `.env.example`.

Заповни необхідні параметри:

| Змінна | Призначення |
|---|---|
| `DJANGO_SECRET_KEY` | Секретний ключ Django |
| `DJANGO_DEBUG` | Режим налагодження |
| `DJANGO_ALLOWED_HOSTS` | Дозволені хости |
| `DB_NAME` | Назва бази даних |
| `DB_USER` | Користувач PostgreSQL |
| `DB_PASSWORD` | Пароль PostgreSQL |
| `DB_HOST` | Адреса сервера бази даних |
| `DB_PORT` | Порт PostgreSQL |

Не додавай `.env` до GitHub. Він містить конфіденційні налаштування.

### 5. Застосування міграцій

Переконайся, що PostgreSQL запущений і база даних створена.

```bash
python manage.py migrate
```

### 6. Створення адміністратора

```bash
python manage.py createsuperuser
```

### 7. Запуск Django

```bash
python manage.py runserver
```

Після запуску відкрий у браузері:

- Застосунок: http://127.0.0.1:8000/
- Адмінпанель: http://127.0.0.1:8000/admin/

## Команди керування даними

У проєкті передбачені окремі команди для збору та збагачення інформації.

### Збагачення даних вакансій

```bash
python manage.py fetch_job_details --limit 100 --retry-done --delay 5
```

Команда намагається отримати додаткову інформацію про вакансії, зокрема опис, тип зайнятості та рівень посади.

Параметри:
- `--limit` — максимальна кількість вакансій за один запуск.
- `--retry-done` — повторна обробка завершених вакансій, у яких бракує окремих полів.
- `--delay` — затримка між запитами.

### Збагачення даних компаній

```bash
python manage.py fetch_company_details --limit 100 --delay 5
```

Команда отримує доступну інформацію про компанії:
- опис;
- галузь;
- вебсайт;
- кількість працівників.

### Експорт даних в Excel

```bash
python export_all.py
```

Після виконання створюється файл `linkedin_jobs_export.xlsx`, який містить два аркуші:

- `Jobs` — інформація про вакансії.
- `Companies` — інформація про компанії.

## Структура проєкту

```text
linkedin-job-parser/
│
├── config/                         # Налаштування Django
├── jobs/                           # Основний застосунок
│   ├── management/

│   ├── exporter.py                 # Експорт в Excel

├── manage.py                       # Керування Django-проєктом
├── export_all.py                   # Експорт усіх даних
├── migrate_data.py                 # Міграція даних, якщо потрібна
├── requirements.txt                # Залежності Python
├── .env.example                    # Приклад змінних середовища
├── .gitignore                      # Файли, виключені з Git
└── README.md                       # Документація проєкту
```

## Безпека та обмеження

- Секретні ключі та паролі зберігаються у змінних середовища.
- Файл `.env`, локальні бази даних і резервні копії не повинні потрапляти до репозиторію.
- Доступність інформації залежить від того, які дані LinkedIn повертає для конкретної вакансії або компанії.
- Під час використання парсера необхідно враховувати правила доступу та умови використання LinkedIn.
